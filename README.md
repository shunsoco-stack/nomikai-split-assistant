# 飲み会の傾斜割り勘・幹事アシスタント

## 概要

「幹事ノート」は、役職や参加時間に合わせて会費を決め、計算の根拠を共有し、集金まで管理できる日本語のWebアプリです。第二営業部の飲み会を想定した、デモ用の架空データを収録しています。

## 主な機能

- **傾斜の設定**：役職区分と重みを編集。個人の固定額を優先して、残額を按分します。
- **遅刻・早退・飲まない人の調整**：到着・退出時刻から滞在割合を計算。滞在割合の下限と飲まない人の係数を変更できます。
- **端数処理**：100円・500円・1,000円単位で切り上げ、切り捨て、四捨五入。切り捨ての不足は幹事・最上位の役職者・均等から選択します。
- **集金チェック**：受領金額・手段・日時を記録。未集金額とリマインド文面を表示し、会費変更後の追加集金・返金額も確認できます。
- **共有**：名前・区分・会費・計算根拠を含むURLや文面をコピー。共有URLだけで結果を表示でき、集金記録は含めません。
- 履歴検索、BOM付きCSV、検証付きJSONバックアップ、既定データへの復元、PWA用manifestとService Worker。

## 計算方法

```text
残額 = max(0, 会計 − 固定額の合計)
滞在割合 = max(設定した下限, 会の時間内の滞在分数 ÷ 会の所要分数)
個人の係数 = 役職の重み × 滞在割合 × 飲酒係数
個人の按分額 = 残額 × 個人の係数 ÷ 固定額以外の係数合計
会費 = 端数処理後の按分額 ＋ 切り捨て時の不足負担
集金合計 = 会計 ＋ 余り − 不足
```

例：会計20,000円、部長は8,000円固定。残る2名の係数が1.0と0.8なら、12,000円を6,667円と5,333円に配分します。100円単位の切り上げでは6,700円と5,400円になり、集金合計20,100円、余り100円です。

係数は整数の基準値に変換し、配分の積と除算にはBigIntを使います。滞在割合は1万分率の切り捨て、設定係数は小数点以下2桁までです。1円未満は最大剰余法で配分し、同順位は参加者の表示順を優先します。金額はすべて整数円です。

固定額の人は飲酒・滞在による調整、端数処理、不足負担から除外します。最上位の役職者は対象者の役職の重みで判断し、同順位は表示順です。幹事が固定額または重み0なら、幹事負担を自動で他の人に移さず、不足を残して通知します。均等負担の1円未満も表示順に配分します。追加負担後は指定した単位の倍数にならない場合があります。

重み0のゲストには請求せず、その分を他の対象者が負担します。全員ゲスト・参加者ゼロ・係数合計ゼロの場合は未配分額を不足として表示し、会社負担等を別途確認します。固定額が会計を超える場合は超過を余りとして表示します。四捨五入の不足は自動加算せず表示します。コース・飲み放題の有無は会の記録項目で、係数を自動変更しません。

## 日時の扱い

日付は日本時間の`YYYY-MM-DD`、時刻は`HH:MM`です。今日の日付・初回シード・localStorageの読込はクライアントのマウント後に確定し、サーバー描画との不一致を防ぎます。集金日時はISO形式で保存し、画面では日本時間で表示します。会の時間は同日内で設定します。

初回シードは開いた日時から生成します。過去8件は直近約12か月の金曜に分散し、うち3件は月の最終金曜を選びます。月に合わせて歓迎会・送別会・暑気払い・忘年会などを選びます。集金中の会は前日以前の直近の金曜、予定の会は翌日以降の金曜です（金曜の18時前に開いても翌週を選びます）。集金記録は当日から5日後の範囲で、すべて生成時点より前です。0時台でも未来の集金を作りません。生成済みのデータは時間の経過では書き換えません。

## 既存作品との違い

| 作品                   | 主な目的                   | この作品との違い                                                               |
| ---------------------- | -------------------------- | ------------------------------------------------------------------------------ |
| 経費精算・承認システム | 経費の申請・承認           | 本作は飲み会の会費配分と集金記録に集中し、申請・承認を持ちません。             |
| 日当・手当・交通費精算 | 業務に伴う費用・手当の算定 | 本作は滞在時間・役職・飲酒の有無による割り勘を扱い、交通費・日当を扱いません。 |

## データの保存先

ブラウザのlocalStorage、キーは`nsa:v1`です。バージョン・日付・時刻・金額・係数・参照ID・重複IDを検証し、壊れた保存データはデモデータへ戻して通知します。保存できない環境では通知を表示し、その画面内で一時的に動作します。別端末との同期はありません。

共有URLはUTF-8 JSONをBase64URL化したスナップショットをクエリに持ち、サーバーへの保存を必要としません。受信時は型・文字数・値域・合計一致を検証します。URLを知る人は内容を閲覧でき、作成者の認証は行いません。長いURLが送信先で省略される場合は文面コピーをご利用ください。

JSON読込みでは2MBを上限に検証し、置換前に件数を確認できます。CSVはBOM・CRLF・引用符のエスケープ付きで、数式として解釈される文字列を無効化します。ファイル名は`割り勘_会の名前_開催日.csv`です。

Service Workerは本番だけで登録します。訪問済みページと静的アセットをネットワーク優先でキャッシュし、接続できないときに利用します。共有URLはキャッシュ対象外です。初回アクセスにはネットワークが必要です。

## ローカル起動方法

Node.js 24.18以降を推奨します。テストはNode.jsのTypeScript型除去機能で純粋関数を直接読み込みます。

```powershell
cd nomikai-split-assistant
npm install
npm run dev
```

本番相当の確認：

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

整形：

```powershell
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

静的書き出しを利用する場合：

```powershell
$env:NSA_STATIC_EXPORT = "1"
npm run build
Remove-Item Env:NSA_STATIC_EXPORT
```

出力先は`out/`です。任意の会IDはビルド時には存在しないため、静的ホスト側で`/events/*`へのアクセスに`out/events/local.html`をHTTP 200で配信するフォールバックを設定します。元のURLを保持すれば、共通の画面がパスからIDとタブを読み取り、localStorageの会を表示します。`split`・`collect`のサブパスも同じフォールバックで動きます。404ページにも同じ復元画面がありますが、HTTP 404を避けるにはホストのフォールバックが必要です。通常の`npm start`ではホスト側の追加設定は不要です。

## デモデータについて

人物・部署・会場・金額・記録はすべて架空です。初回は過去の会8件、未集金3名の会1件、予定1件を作成します。人数6〜18名、開催時刻・滞在・飲酒・固定額・メモは会ごとに個別設定しています。名前をランキング順に並べたり、配列の順送りで会を作ったりしません。歓迎会は4〜5月、暑気払いは7〜8月、忘年会は12月、送別会は3月に合わせ、打ち上げには「展示会」「新システム導入」など具体的な名前を付けています。10件の中で同じ会名・同じ店はそれぞれ最大2回、会場は7店、会計額はすべて異なります。会名に「・予定」「（架空）」は付けません。

開催済みの会計は1人4,000〜7,000円程度で、端数を含みます。予定の会はコース5,500円×10名＝55,000円の見込み額です。一覧・会の設定・割り勘結果に「見込み」と表示し、幹事メモにも計算の根拠を記載しています。人数や追加注文が確定したら会計を更新する想定です。2026年11月18日（水）14:30に初めて開くと、集金中は11月13日（金）、予定は11月20日（金）になります。保存済みデータには自動適用されないため、変更後のシードを確認する場合は「このアプリについて」から既定データへ復元してください。

テストは端数3種類×3単位の境界、固定額、極端な係数、不足負担、3,000回の乱数検算、集金、共有URL、不正入力、CSV、バックアップ、複数の日本時間でのシードを確認します。シードの重複・見込み額・季節・金曜日の検証には、水曜14:30、金曜17:00・18:00・20:00、月曜0:20、各月の月初・月半ば・28日、月末、年末年始、うるう日を含む47基準日時を使います。
